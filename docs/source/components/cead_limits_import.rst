4. Моделі даних
***************

Нижче наведено опис моделі **AppLimited**, що є основною моделлю Підсистеми
для зберігання даних щодо обмежень публікації заявки.

* Таблиця в базі даних: **ls_limited_applications**

**Поля моделі:**

* app_number
    * Опис: Номер заявки.
    * Тип даних: CharField
    * Довжина: до 16 символів.
    * Індексація: db_index=True.

* obj_type
    * Опис: Тип об'єкта.
    * Тип даних: Зв'язок із моделлю ObjType (ForeignKey).
    * Колонка в таблиці: idObjType.
    * Додаткові параметри:
        * Значення може бути порожнім (blank=True, null=True).
        * При видаленні пов'язаного об'єкта записи цієї моделі також видаляються (on_delete=models.CASCADE).

* settings_json
    * Опис: Налаштування публікації у форматі JSON.
    * Тип даних: TextField.
    * Додаткові параметри:
        * Значення може бути порожнім (blank=True, null=True).
        * Значення за замовчуванням: порожній JSON ('{}').
        * Підказка: "Налаштування публікації у форматі JSON".
    * Поля JSON, що можуть бути наявні (кожне поле містить булеве значення (true/false), що є ознакою чи має відображатися це поле):
        * **Винаходи, корисні моделі, топографії інтегральних мікросхем**:
        * 'I_71' - ім’я або повне найменування заявника (заявників);
        * 'I_72' - ім’я винахідника (винахідників);
        * 'I_73' - ім’я або повне найменування та адреса володільця(ів) патенту;
        * 'I_98' - адреса та ім’я фізичної або повне найменування юридичної особи, якій надсилається патент, адреса для листування;
        * 'I_98_Index' - поштовий індекс;
        * 'CL' - формула;
        * 'DE' - опис;
        * 'AB' - реферат;
        * 'I_54' - назва патенту;
        * 'I_56' - аналоги патенту;
        * 'I_74' - найменування представника;
        * **Торговельні марки**:
        * 'ApplicantDetails' - дані щодо заявника;
        * 'HolderDetails' - дані щодо власника;
        * 'CorrespondenceAddress' - адреса для листування;
        * 'MarkImageColourClaimedText' - інформація про заявлені кольори;
        * 'MarkImageFilename' - зображення;
        * 'RepresentativeDetails' - дані щодо представника;
        * 'GoodsServicesDetails' - МКТП;
        * **Промислові зразки**:
        * 'DesignSpecimenDetails' - зображення промислового зразка;
        * 'ApplicantDetails' - ім’я або повне найменування та адреса заявника (заявників);
        * 'DesignerDetails' - ім’я автора (авторів);
        * 'HolderDetails' - ім’я або повне найменування та адреса власника(ів) промислового зразка;
        * 'CorrespondenceAddress' - адреса та ім’я фізичної або повне найменування юридичної особи, якій надсилається свідоцтво, адреса для листування;
        * 'DesignTitle' - назва промислового зразка;
        * 'RepresentativeDetails' - Найменування представника;
        * **Авторське право на твір, Авторське право на службовий твір**:
        * 'AuthorDetails' - прізвище, ім’я по батькові (за наявності) та/або псевдонім автора (авторів);
        * 'ApplicantDetails' - дані щодо заявника;
        * 'PromulgationData' - відомості про оприлюднення твору;
        * 'Annotation' - анотація або реферат твору;
        * 'HolderDetails' - прізвище, ім’я, по батькові або повне найменування особи (осіб), якій (яким) належать майнові права на твір;
        * 'EmployerDetails' - дані щодо роботодавця;
        * 'RepresentativeDetails' - прізвище, ім’я, по батькові (за наявності) або повне найменування представника;
        * 'Name' - назва твору;
        * 'NameShort' - назва твору (коротка);
        * **Договори про передачу права на використання твору, Договори про передачу (відчуження) майнових прав на твір**:
        * 'LicenseeDetails' - прізвище, ім’я, по батькові або повне найменування осіб – сторін договору (ліцензіат);
        * 'LicensorDetails' - прізвище, ім’я, по батькові або повне найменування осіб – сторін договору (ліцензіар);
        * 'RegistrationKind' - вид і назва договору;
        * 'RegistrationKindCode' - вид і назва договору (код);
        * 'AuthorDetails' - прізвище, ім’я по батькові та/або псевдонім автора (авторів);
        * 'ApplicantDetails' - дані щодо заявника;
        * 'Annotation' - анотація або реферат твору;
        * 'Name' - назва твору;
        * 'NameShort' - назва твору (коротка);
        * 'RepresentativeDetails' - прізвище, ім’я, по батькові (за наявності) або повне найменування представника;

* reason
    * Опис: Причина обмеження даних або зняття обмежень.
    * Тип даних: TextField.
    * Додаткові параметри: Значення може бути порожнім (blank=True, null=True).

* cancelled
    * Опис: Вказує, чи зняті обмеження.
    * Тип даних: BooleanField.
    * Значення за замовчуванням: False.
    * Підказка: "Якщо опцію активовано, то дані об'єкта відображатимуться у повному обсязі".

**Метадані**

    * Назва моделі в однині: "Обмежена публікація".
    * Назва моделі у множині: "Обмежені публікації".
    * Обмеження:
        * Унікальність за полями app_number та obj_type (назва обмеження: unique app_number_obj_type).

**Додаткові методи та властивості**

    * __str__
        Повертає номер заявки (app_number) як рядкове представлення об'єкта.

    * settings_dict
        * Тип: Властивість (@property).
        * Повертає налаштування публікації у вигляді словника, перетворюючи вміст поля settings_json із JSON-рядка.

    * save
        * Перевизначає метод збереження об'єкта.
        * Додаткова логіка:
            * При збереженні об'єкта оновлюються поля elasticindexed та lastupdate у пов'язаних записах таблиці
              IPCAppList для відповідних значень app_number та obj_type_id.

**Залежності**

    * Пов’язані моделі:
        * ObjType (через поле obj_type).
        * IpcAppList (оновлення даних при збереженні).
    * Вбудовані бібліотеки:
        * json для роботи з JSON.
        * datetime для отримання поточного часу.

5. Конфігурація
***************

Для коректної роботи Підсистеми необхідно вказати параметри підключення до баз даних
EArchive (ЦЕАД) та UMA (СІС) у файлі *uma/settings.py*. Редагувати, за необхідності, треба словник (dict) **DATABASES**
, а саме значення клчів **default** та **e_archive**:

.. code-block:: python

    DATABASES = {
        'default': {
            'ENGINE': 'mssql',
            'NAME': 'UMA',
            'USER': '',
            'PASSWORD': '',
            'HOST': '10.10.18.1',
            'PORT': '1433',

            'OPTIONS': {
                'driver': 'ODBC Driver 18 for SQL Server',
                'extra_params': "TrustServerCertificate=yes;MARS_Connection=Yes"
            },
        },

        'e_archive': {
            'ENGINE': 'mssql',
            'NAME': 'EArchive',
            'USER': '',
            'PASSWORD': '',
            'HOST': '10.11.11.10',
            'PORT': '51433',

            'OPTIONS': {
                'driver': 'ODBC Driver 17 for SQL Server',
            },
        },
    }

6. Логіка взаємодії
*******************

6.1. Взаємодія з іншими підсистемами
####################################

Підсистема взаємодіє із базою даних **EArchive** (Центральний електронний архів документів) для отримання даних щодо
обмежень публікації об'єктів права інтелектуальної власності. Для отримання даних у БД EArchive було розроблено
збережені процедури:

.. list-table:: Опис збережених процедур у БД EArchive:
   :width: 100 %
   :widths: 25 75

   * - **[ext].[uma_GetLimitObjects]**
     - | Повертає dataset  об'єктів, за якими змінився
       | статус обмеження публікацій
       | (або змінився перелік обмежених реквізитів).
   * - **[ext].[uma_GetLimitsInfoForObject]**
     - | Повертає статус та перелік обмежених реквізитів
       | (за наявності)

6.2. Вхідні та вихідні дані
###########################

**Вхідні дані:**

Параметр команди **days** (ціле число), що визначає кількість днів, за які необхідно отримати та обробити інформацію.
Наприклад, days=7 означає вибірку даних за останні 7 днів.

**Вихідні дані:**

Створені/оновлені записи у БД UMA (СІС) за допомогою моделі AppLimited.

    Exported objects count: 2

************************
8. Приклади використання
************************

Оновити дані за 1 день:

.. code-block:: bash

    poetry run python manage.py cead_limits_update --days=1

Варто відмітити, що після виконання команди необхідно також запустити процес пошукової індексації для того,
щоб обмеження даних почали відображатися у СІС.

Також доцільно помістити команду у crontab для регулярного оновлення даних.
